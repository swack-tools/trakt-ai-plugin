A multi-user Rust/WASM Cloudflare Worker at https://trakt.swacktech.com. Each person connects their own Trakt account. No shared Trakt login or operator credentials are required by users.

For step-by-step setup in Claude, Codex, and ChatGPT, use the client guide.

Connect a client

For Claude Code's modern HTTP transport:

claude mcp add --transport http trakt https://trakt.swacktech.com/mcp

Open /mcp in Claude Code and authenticate. The browser shows which client is requesting access. Choose Connect Trakt, sign in, and approve at Trakt. When Trakt sends you back, choose Return to your app.

For legacy clients, use https://trakt.swacktech.com/sse. The .claude-plugin manifest explicitly points to its SSE configuration. For local plugin testing, clone this repository and run claude --plugin-dir .. The repository is public. The root legacy plugin still uses SSE; the repository marketplace packages use modern HTTP. See the client guide for current marketplace installation instructions.

Codex and other OAuth-capable MCP clients can use https://trakt.swacktech.com/mcp. Configure it as a remote HTTP MCP server and use that client's login flow. OAuth discovery, dynamic client registration, S256 PKCE, authorization-code exchange and rotating refresh tokens are provided. Public clients must support PKCE.

List and calendar tools

trakt_discover_lists browses trending or popular public lists, with an optional genre slug filter and page/limit. It does not search list titles. trakt_get_list_items fetches a page of movie, show, or all items by owner and list ID. trakt_get_calendar accepts a kind (shows, new_shows, premieres, finales, movies, streaming, or dvd), a personal or public target, an ISO start date, and a 1–31 day window. Follow returned pagination for complete list results; a calendar result does not prove streaming availability.

trakt_create_list creates a personal list, private by default. trakt_add_list_items and trakt_remove_list_items accept an owned list ID and up to 100 distinct movie, show, season, or episode Trakt IDs. Every write requires confirmed: true and an OAuth connection with trakt:write. Before updating or deleting a list or editing its items, the server compares the list owner with the connected Trakt account and refuses an unverifiable or foreign list. Check a list after an uncertain write response; never automatically replay it. Successful tool responses retain JSON text and expose the same result in versioned structuredContent. Each tool advertises an output schema for clients that validate structured responses.

Recommendations preserve Trakt's own ranking and preference signals. The service does not train an additional ratings model. The watched tool defaults to mode=all: one page of /sync/watched/{movies|shows} title summaries with play counts. mode=recent reads /sync/history/{movies|shows} chronological events, newest first, preserving repeated watches. Show history may contain episode events; a show summary does not establish completed viewing. Search filters apply to the fetched upstream page; filters_applied_to_page and original pagination counts make this explicit.

Watched and search pagination

trakt_get_watched_history accepts media_type=movie|show|all, mode=all|recent (default all), page (integer, at least 1; default 1), limit (1–100; default 100), and detail=compact|full (default compact). Each call fetches one page per requested medium. Compact detail reduces payload size for traversal; full detail preserves the upstream metadata for specific needs. For one medium the response contains data and pagination; for all, each is nested under movies and shows.

Compact rows retain supplied plays, last_watched_at, last_updated_at, total_count, history id, watched_at, action, and type. Movie/show objects retain ids, title, year, genres, released, first_aired, and runtime; episodes retain ids, title, season, and number. Only supplied fields are included. The detail parameter applies only to watched history; search and recommendations do not accept it.

Watched and search pagination exposes page, effective limit, page_count, item_count, has_more, and next_page. Follow the returned next page until has_more is explicitly false and next_page is null to retrieve a complete dataset; do not calculate completion from the requested limit because Trakt may clamp it. Unknown continuation metadata means partial coverage, even when the next page is null. Keep the same requested limit throughout a traversal. With both media, continue each stream independently using its own media type. The service does not aggregate every page in one call.

The bundled skills explicitly use detail=compact for both history modes and retrieve every summary page for all-history requests and recommendations based on all viewing, tracking media-qualified IDs and counts with progress updates. They stop with partial coverage and a resume page on errors, truncated output, or inconsistent pagination, and honor retry delays. Recent-viewing workflows collect only the first 100 chronological events per medium, following extra pages if the effective limit is smaller. Repeated watches remain distinct events; this bounded recent view does not establish every watch in a calendar period.

Ordinary title search stays bounded; explicitly requesting all search results follows every next_page, including after an empty filtered page. Recommendations support a result limit up to 100; upstream documentation does not establish a page parameter, so this tool exposes none.

Documented API coverage

The catalog under api/trakt represents the 335 operation pages in the captured official Trakt reference index. It is the server's allowlist: each operation retains its source reference, method, path, parameter and body schemas, authentication requirement, category, pagination support, and availability status. A catalog snapshot is not a promise to include future API additions automatically.

The reviewed file api/trakt/tools.json decides what is exposed. Each tool names one operation, or a map from one input to operations such as one action across movie, show, and episode. Its inputs are fixed; no tool accepts a free-form path, method, operation ID, raw URL, header, token, or request body. Each call is checked against the tool's schema and then the operation's schema. The server sends requests only to the configured Trakt API.

StatusMeaning
supportedA tool can map to the operation, subject to schema validation, authorization, account eligibility, and upstream limits.
managed_authThe service manages authentication itself; no tool forwards these token or device operations.
unavailableThe operation is represented for coverage but no tool can call it, for example because of a first-party restriction.

Most tools respond with operation_id, upstream status, data, and pagination. Data can be an object, array, or empty result. A paginated read performs one request, with a default limit of 20 on most tools; Trakt can clamp that limit. The response reports the effective pagination. No headers means unknown continuation, not a complete account export. Keep the requested limit fixed when continuing. Rate limits, account restrictions, and partial write results still apply.

Write permission and verification

New browser OAuth connections request trakt:read trakt:write if scope is omitted. The consent page identifies the requested write access. An explicit trakt:read request remains read-only. Existing tokens and standalone device login remain read-only; reauthorize through the client for writes. Refresh preserves the original scope and cannot elevate it.

A write requires trakt:write and confirmed: true for a concrete change the user requested. Clear existing intent is sufficient; ask only for unresolved targets or effects. Recommendation and discovery workflows never imply permission to save, rate, or mark a title watched. Read back the relevant state after a write and report per-item failures. Never automatically repeat a write after a timeout or ambiguous error: Trakt might already have applied it.

Trakt allows one authenticated POST, PUT, or DELETE per second per user. The service waits as needed so a list's ownership read, the write, and the next read on that connection stay at least one second apart.

write_authorization_required requires client reauthorization. confirmation_required means explicit write intent was not supplied. On invalid_parameters, read the tool's input schema and correct the call once. Other errors include trakt_not_found, trakt_forbidden, trakt_validation_failed, trakt_rate_limited, trakt_upstream_error, and trakt_unavailable. Honor retry guidance for reads; uncertain writes require state inspection.

OpenAPI Actions and HTTP

Import https://trakt.swacktech.com/openapi.json. The API supports OAuth authorization code and client_secret_post for confidential Actions clients:

  1. Obtain the exact callback URL displayed by the Actions client.
  2. POST /oauth/register with client_name, redirect_uris: ["<exact callback>"], and token_endpoint_auth_method: "client_secret_post".
  3. Save the returned client_id and client_secret in the Actions client's OAuth configuration. Never put the secret in the schema or chat.
  4. Set authorization URL to /oauth/authorize, token URL to /oauth/token, scope to trakt:read for reads or trakt:read trakt:write for requested writes, and token exchange to POST body credentials.

Public OAuth clients use token_endpoint_auth_method: "none" and S256 PKCE. Instead of registering, a public client can use an HTTPS client_id that serves a Client ID Metadata Document; the server fetches it during authorization (only from claude.ai and chatgpt.com, no redirects, five-second timeout, 5 KiB limit), requires its client_id to equal the URL, and names that URL's host on the consent page. The consent page also warns when the redirect stays on the user's device. Redirect URIs must be exact registered HTTPS URLs or local loopback HTTP URLs; a loopback redirect matches its registered host and path on any port. Each transport's protected resource metadata names its own URL, https://trakt.swacktech.com/mcp or https://trakt.swacktech.com/sse, and an unauthenticated request's WWW-Authenticate header points to the matching document. The origin metadata keeps the shared https://trakt.swacktech.com/ identifier that earlier clients negotiated, and the server accepts all three. This is an OAuth/API integration; importing the schema alone does not register or publish an app in any marketplace.

Standalone device login creates a read-only connection. For an interactive command-line login, run python3 scripts/login.py; it displays the activation code and saves plugin credentials privately under your user configuration directory.

Direct HTTP clients can POST {} to /auth/device/code. Save the returned session_token privately and display user_code, verification_url and instructions. After at least interval seconds, POST {"device_code":"..."} to /auth/device/token with Authorization: Bearer <session_token>. On success, replace the temporary token with the returned plugin access_token and securely save refresh_token. These are plugin credentials, never Trakt credentials. Plugin access tokens last one hour; refresh tokens expire after 30 days and rotate on every use. Reusing an already-consumed refresh token revokes that connection; reauthorize after 1,024 rotations. Exchange a direct-login refresh token at /oauth/token with grant_type=refresh_token; no client ID is needed for direct login. OAuth client-bound refreshes require the original client ID and, for confidential clients, client secret.

Authenticated data endpoints:

GET /sync/watched?media_type=all&mode=all&page=1&limit=100&detail=compact
GET /sync/watched?media_type=movie&mode=recent&page=1&limit=100&detail=compact
GET /recommendations?media_type=movie&genres=science-fiction&years=2020-2026&limit=10
GET /search?query=Arrival&media_type=movie&page=1&limit=20
DELETE /auth/session

Errors return JSON with a stable error code, an error_description that explains the next step, and retry_after when a delay applies. Tool failures carry the same object as their text result.

Device polling statuses: 400 pending, 404 invalid code, 409 already used, 410 expired, 418 denied, 429 slow down. Respect Retry-After; do not retry non-idempotent token exchanges blindly. DELETE /auth/session signs out: it asks Trakt to revoke access, then deletes the grant and every connection sharing it. It returns 204, or 200 with trakt_revoked: false when Trakt did not confirm revocation; revoke the app in Trakt settings in that case.

Deployment

Prerequisites: Node 22+, rustup stable with wasm32-unknown-unknown, GitHub command-line tool and Wrangler authentication, SSH/GPG commit signing, and the .env.example variables in ignored .env. Configure the Trakt app to allow device authentication, and add {PUBLIC_BASE_URL}/oauth/trakt/callback as a redirect URI. Browser login and token refresh use it.

Bring your own deployment

Copy .env.example to ignored .env and supply your own account ID, Worker API token, Trakt app credentials, token-seal keys, DNS hostname, and zone. For example, a hostname watch.example.org belongs to zone example.org. Both public URLs and namespace names are configuration rather than credentials, but no operator-specific values are supplied by the example.

PUBLIC_BASE_URL is optional for the configuration helper and must match your configured hostname if set. The static openapi.json uses a non-routable example origin; the Worker’s /openapi.json rewrites it to your configured public origin. End-user marketplace packages intentionally connect to the documented hosted service; change their MCP URLs and skill dependency metadata too when distributing a self-hosted variant.

TOKEN_SEAL_KEYS is required JSON: {"index":"<64 hex>","keys":[{"kid":"k1","key":"<64 hex>"}]}. index keys user and address hashes, so changing it orphans every grant. To rotate a sealing key, add the new key and set retired_at (Unix seconds) on the old one; it then only opens existing credentials, for 30 days.

OPENAI_APPS_CHALLENGE is optional. Only after the portal issues a token, configure that exact value securely; the challenge route returns it as plain text, or 404 when unset. This does not prove domain verification occurred.

Pull requests run the validation workflows. Pushes to main build and deploy the Worker with encrypted Worker secrets; they do not rerun the test suite. Review the pull request checks before merging. Set CLOUDFLARE_PLUGIN_DNS and CLOUDFLARE_ZONE_NAME as GitHub repository variables before enabling a main-branch deployment. Use your own DNS hostname and explicit Cloudflare zone; the workflow has no production-host fallback. scripts/manage.py configure derives PUBLIC_BASE_URL from that hostname and substitutes the API routes, OAuth metadata, OpenAPI URLs, and allowed own-origin. The deployment creates SQLite Durable Objects through migrations v1 to v3, where v3 erases the older class that held unencrypted Trakt tokens, and installs the API/auth routes listed in wrangler.toml.example. workers.dev and preview URLs are turned off. .env and generated artifacts are ignored. Cargo.lock and package-lock.json are committed; CI and the documented Rust commands use the Cargo lockfile for reproducible dependency resolution.

Isolation and operational limits

  • Trakt tokens are stored encrypted with a key held only by your AI clients; records are deleted 30 days after last use or on sign-out. It is decrypted in memory only while handling a request.
  • Each Trakt user has one Durable Object holding that user's grant, encrypted with AES-256-GCM under a 256-bit connection key K and keyed by an HMAC of the Trakt user ID. K is sealed into plugin credentials under TOKEN_SEAL_KEYS and never stored. Each connection has its own Durable Object with hashed plugin credentials and its permission. The grant's Durable Object serializes single-use Trakt refreshes and paces each user's writes.
  • Trakt tokens refresh only near expiry. A 429 on refresh keeps the grant, because Trakt did not use the refresh token. The client gets trakt_rate_limited with retry_after, from Trakt's Retry-After or a 60-second default, and nothing retries automatically.
  • A Durable Object alarm deletes grant and connection records 30 days after last use. That alarm cannot revoke access at Trakt, because K is not available to it. See the privacy page for deletion and infrastructure limitations.
  • No tokens or request bodies are logged by app code. A 429 from Trakt logs whether it came from login or the API, plus Trakt's rate limit header. Responses use no-store; browser login has a restrictive CSP and no third-party scripts. OAuth codes expire after two minutes and are single use. Browser login tickets expire after fifteen minutes.
  • Browser origins are allowlisted for this domain, ChatGPT, and Claude. Native clients send no Origin. Authentication is enforced independently of CORS. Public registration/login starts are limited to 20/minute per source IP, except that Anthropic's published egress range (160.79.104.0/21), which registers clients for every hosted Claude user, shares one 600/minute limit; authenticated requests are limited to 120/minute per connection. Temporary login credentials cannot access data tools. Deployments intended for heavier public traffic should tune abuse and cost limits for their needs.
  • Request bodies are capped at 64 KiB, upstream responses at 8 MiB, and upstream requests at 20 seconds. Oversized responses fail explicitly. Full JSON processing allocates memory; this service does not claim zero-allocation serialization.
  • Tool results carry at most 60,000 characters of JSON text plus the same data as structuredContent, which fits Claude's result limits; a larger result fails with tool_result_too_large instead of arriving truncated. A write whose result is too large fails with write_result_too_large, because Trakt already accepted it. That error includes operation_id and the upstream status: read the data back instead of repeating the write. Streamable HTTP returns JSON and accepts notifications with 202. A request whose MCP-Protocol-Version header names a revision other than 2025-06-18, 2025-03-26, or 2024-11-05 gets 400. GET /mcp returns 405. Legacy SSE supports up to eight streams per connection with bounded queues and a 3 MiB event limit (including both JSON text and structured output); transport state is ephemeral, so reconnect and initialize after disconnection. It does not claim event replay.
  • Integration tests use fake Trakt accounts in local workerd. They do not modify real viewing history. Deployment checks establish infrastructure behavior; a human must approve Trakt login to verify live personal history/recommendations.

Manual skill behavior checks

Run python3 scripts/check_skill_behaviors.py to exercise list creation, a personal calendar, and rating/collection changes with the installed Codex command-line tool. This optional check uses your existing Codex login and model quota. It copies all seven skills to fresh temporary workspaces and connects only to the local stdio fixture. The fixture makes no HTTP requests and uses no Trakt credentials.

The runner keeps the read-only shell sandbox and grants approval only to the fixture's write tools each scenario needs. It checks exact requested writes, successful readbacks, and rejection of an injected request to change history. It preserves traces and final responses in the printed artifact directory. Review each result.txt for wording and time-zone presentation. These model-based checks are manual and do not run in CI.

python3 scripts/check_skill_behaviors.py
python3 scripts/check_skill_behaviors.py --check-traces /path/to/saved-run

Saved runs contain lists/trace.jsonl, calendar/trace.jsonl, and library/trace.jsonl. Use --scenario calendar to check one scenario, or --include-recommendations for an additional read-only scenario. Use a fresh --output directory for a new run; the runner preserves existing artifacts.

Documentation deployment

This site is deployed by .github/workflows/docs.yml through GitHub Actions. Pull requests generate and validate the static site. Pushes to main build the Pages artifact and deploy it to the github-pages environment without rerunning documentation checks. Repository Settings → Pages uses GitHub Actions as its source.

The canonical documentation address is https://trakt.swacktech.com/. GitHub Pages owns the static site origin; a proxied Cloudflare CNAME points trakt to swack-tools.github.io. Cloudflare Worker routes preserve /mcp, legacy SSE, API endpoints, OAuth discovery, registration, login assets, and device authentication on this same hostname. Documentation requests do not run through the API Worker.

Set the repository’s Pages custom domain to trakt.swacktech.com while retaining the GitHub Actions publishing source. Actions publishing ignores a CNAME artifact; the repository setting is authoritative. Cloudflare’s Worker Custom Domain must be removed during the coordinated DNS handoff because it otherwise owns every path. Retain the existing Worker, Durable Objects, and KV namespace. For this hosted deployment, GitHub Enforce HTTPS is enabled and a hostname-specific Cloudflare Full (strict) rule validates the origin certificate. That setting is managed outside Wrangler. A new deployment must configure and verify its own DNS, certificates, and GitHub Pages domain; copying the Worker config does not perform those steps. DNS setup requires a separate token with Zone DNS Edit permission if the Worker token lacks it.

When adding an API path, update its Worker route and run python3 scripts/check_routes.py. This check verifies every handler path, including query strings, and confirms generated documentation files bypass the Worker. See the Cloudflare route rules and GitHub Pages custom-domain setup.

TRAKT_DOCS_PREVIEW=$(mktemp -d)
python3 docs/build.py "$TRAKT_DOCS_PREVIEW"
python3 docs/check.py "$TRAKT_DOCS_PREVIEW"
python3 -m http.server 8080 --directory "$TRAKT_DOCS_PREVIEW"

Each preview build uses a fresh temporary directory; stop the previous preview server before starting it again. Site generation uses Python’s standard library. It requires no package installation or JavaScript. Edit the HTML fragments in docs/pages/ and styles in docs/assets/.
